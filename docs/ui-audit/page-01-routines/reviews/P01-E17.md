## Diagnostic du code réel

Le panneau actuel distingue déjà le chargement sans donnée, l'indisponibilité et la sélection vide, mais ces états ne forment pas encore un contrat cohérent. Le chargement utilise un emoji différent de W6; l'indisponibilité ajoute un paragraphe long et une icône pleine; la sélection vide laisse « Tenue prête » active; Réinitialiser n'indique pas clairement si l'état a changé. L'actualisation avec une météo déjà affichée ne doit déclencher aucun de ces écrans.

La décision doit donc fixer cinq comportements ensemble : chargement initial, météo indisponible, sélection vide, réinitialisation et accès aux réglages météo.

## Q1 — Continuité calme — recommandé

Le panneau conserve exactement la même structure dans tous les états. Le chargement sans donnée montre une petite représentation W6 et « Météo en cours… ». L'indisponibilité montre « Météo indisponible », puis un bouton secondaire « Réglages météo ». Une sélection vide laisse la grille visible, affiche une alerte courte et désactive « Tenue prête ». Réinitialiser restaure immédiatement la proposition automatique, sans confirmation ni notification supplémentaire.

- Mobile : état centré dans le bottom sheet; grille et alerte tiennent dans le contenu défilable; pied fixe.
- Tablette et bureau : mêmes blocs dans le panneau latéral; « Regardons le ciel » apparaît seulement dans l'état indisponible à partir de 768 px.
- Accessibilité : chargement annoncé une fois avec `status`; indisponibilité et sélection vide annoncées sans répétition; le bouton désactivé expose son état; le focus revient sur la première carte restaurée après Réinitialiser.
- Avantage : emplacement, vocabulaire et action principale restent prévisibles.
- Risque : sans météo, le parent doit ouvrir les réglages avant de préparer une proposition guidée.

## Q2 — Action contextuelle

Le contenu reste stable, mais l'action principale du pied change selon le problème : indisponible pendant le chargement, « Ouvrir les réglages » sans météo, « Restaurer la proposition » avec une sélection vide et « Tenue prête » dans l'état nominal. Réinitialiser disparaît lorsqu'il ferait doublon.

- Mobile : une seule grande action contextuelle dans le pied du bottom sheet.
- Tablette et bureau : même logique dans le panneau latéral; aucun texte supplémentaire.
- Accessibilité : le nouveau libellé est annoncé à chaque transition d'état et le focus reste dans le pied.
- Avantage : la prochaine action utile est toujours évidente.
- Risque : le bouton principal change de sens et de position mentale, ce qui réduit la prévisibilité du panneau.

## Q3 — Repli manuel

Quand la météo est indisponible, le panneau affiche les vêtements configurés les plus courants et permet une préparation manuelle. Le parent peut donc continuer hors ligne. Une sélection vide reste valide; « Tenue prête » ferme le panneau même sans vêtement. Réinitialiser recharge la sélection manuelle de départ.

- Mobile : courte grille manuelle dans le bottom sheet; aucune étape supplémentaire.
- Tablette et bureau : grille identique dans le panneau latéral, accompagnée de « Regardons le ciel ».
- Accessibilité : chaque vêtement garde son rôle de case à cocher; l'absence de recommandation météo est annoncée avant la grille.
- Avantage : la tâche peut être terminée même sans service météo.
- Risque : l'application présente des vêtements sans contexte météo et peut créer une fausse impression de recommandation fiable.

## Recommandation

**Q1 — Continuité calme.** Cette option protège le contrat visuel validé de S1, évite une action principale qui change de sens et empêche de valider accidentellement une tenue vide. Elle sépare aussi clairement la panne météo de l'actualisation invisible déjà décidée.
